# NOVA CORE GAP LEDGER — what the compiler/core is lacking (2026-07-03)

> **Purpose.** The 9 frameworks (Forge, Reactor, Cortex, Mesh, Prism, Pulse, Sentinel, Edge, Ops)
> all stand on ONE core: the self-hosted compiler + the C runtime + the type system. **A framework
> inherits every flaw of the core, multiplied by its own size.** So the core must be *good* before
> we pour years into frameworks. This file is the single, honest, prioritized list of what "good"
> still requires.
>
> **Source.** Derived from the 26-agent deep audit of 2026-07-03 (all 140 docs + the 21,967-line
> `nova_compiler.nova` + the ~20,900-line `nova_runtime.c` + Forge + CI + benchmarks read at
> file:line depth, with adversarial claim-checking and a six-language judge panel). Every gap below
> carries evidence. Nothing here is vibes.
>
> **Scope.** CORE ONLY (compiler, type system, runtime, perf, platform, toolchain, process).
> Framework-specific work lives in FORGE_STATUS.md / per-framework plans, not here.
>
> **The one-line state.** The core is *real and rare* — it self-hosts to a byte-identical fixpoint,
> hits C-class scalar speed with zero annotations, and runs a real concurrency runtime. As of
> **2026-07-06** the foundation is materially stronger: **Tier 0 (runtime soundness) is 100% closed**
> and **Tier 1 is essentially done — the type checker is now SOUND BY DEFAULT** (strict is the default;
> it no longer fails open; 1.0–1.3 + 1.5 closed). What remains for "trustworthy AND general": non-scalar
> performance is still capped by the value model (Tier 2 — the real mountain), exhaustive-match ADTs +
> interfaces (Tier 3 — but **generics themselves already exist**, that ledger claim was stale), N>1
> concurrency regresses (Tier 4), and reach/toolchain are thin (Tiers 5–6). Every one is fixable.

## How to read this

Each gap has: **what it is · evidence (file:line) · which frameworks it blocks · effort · fix direction.**
Effort key: **S** = days · **M** = weeks · **L** = 1–3 months · **XL** = multi-month campaign.
Tiers are a *build order*, not a priority ranking of importance — you cannot safely do Tier 2 perf
work while Tier 0 soundness holes make every result untrustworthy.

## TIER 1 — Type-system soundness (the "genius compiler" promise is quietly false today)

NOVA's whole thesis is *the compiler is the genius* (GATE 2: 95% zero-annotation, inference catches
bugs). **As of 2026-07-06 the default checker is SOUND — it no longer fails open** (1.0+1.1+1.2 below).
Remaining Tier-1 items are diagnostics/expressiveness (1.3 occurs-check, 1.4 enum payloads), not the
core fail-open hole. Kept below with ✅ status for the record.

> **★ 1.0 (PREREQUISITE, THE REAL 1.1/1.2 BLOCKER) — heterogeneous-return inference: ✅ FIXED
> (8fe0394b, 2026-07-06). Unblocks 1.1/1.2.**
> Final (working) design after two reverted attempts: (a) **ti_ DEFERRED collect-and-join** — an
> un-annotated ("open") fn COLLECTS its return-expr types in `ti_ret_seen` (they're often unresolved
> vars at return time) and, AFTER the fn's `ti_solve` resolves them, `ti_ret_join_bind` joins the
> RESOLVED types: int/float/bool are mutually-coercible numerics (a float fn with a `return 0` stays
> float), a differing NON-numeric concrete widens to `any`, unit/nothing/var absorbed; concrete
> agreement preserved (no perf loss). (b) **Track genuinely-heterogeneous fns** (`ti_fn_hetero`, set
> when the join widened on a real conflict). (c) **IR frt fixpoint SKIPS the refine for hetero fns**
> (`not contains(ti_fn_hetero, fname)`), so a heterogeneous fn stays `any` in `frt` → callers dispatch
> `print_any`/box correctly. Crucially the IR-side `ir_analyze_return_type` is otherwise UNCHANGED —
> an earlier JOIN there perturbed the S4 floatlist/param-type fixpoint and de-typed float list params
> (math3d/physics2d e-156); the hetero-skip achieves the same result without touching that analysis.
> Validated: `classify(1)`→"hello" (print), `_t1probe`/`_anystr`/`_hetreturn_test` correct,
> math3d/physics2d **ok** (0 FAILs), **strict self-compile 0 errors** (all 7 false-rejections gone).
> Reconverged. `_hetreturn_test` guards it in the regression suite.
>
> *(historical) DIAGNOSIS + two reverted attempts below, kept for the reasoning trail:*
> Attempting the budget fix surfaced the real blocker: return-position inference is **strict at BOTH
> levels** (ti_ HM + the IR `ir_analyze_return_type`), so a function whose `return`s disagree in type is
> **false-REJECTED** instead of widening to `any` — 7 cases in the compiler's own source (`eval_expr`
> `-> any`; `move_expr_uses`/`ire_emit_function`/`nova_pkg_*`/`nova_fmt_file_ast` = `return 0` early-exit
> + unit fall-through). The budget hole *masks* all 7. Also **fails small real programs in DEFAULT mode**
> (`_anyret_repro.nova`) — a genuine defect independent of the budget. **Owner-ratified decision ("do
> what you think"): widen un-annotated heterogeneous returns to `any`** (zero-ceremony; `any` is
> first-class), PRESERVING the inferred concrete type when returns agree (no perf loss) and keeping
> STRICT for a concrete annotation.
>
> **ATTEMPT 1 (reverted; patch saved `NOVA_DESIGN/tier1_return_inference_ATTEMPT.patch`):** two mirrored
> tolerant JOINs — ti_ `ti_ret_constrain` + IR `ir_analyze_return_type`. It compiled heterogeneous
> returns, made strict self-compile 0-errors, and reconverged byte-identically — BUT **broke `math3d` +
> `physics2d` (float `e-156` garbage = a raw double read as a boxed pointer).** ROOT CAUSE of the
> regression: the ti_ side used **EAGER `ti_bind`**, but return-expression types are frequently
> unresolved **type VARIABLES** at return-processing time; the eager code *skipped* var-typed returns
> (only binds concrete), so a float fn's return var never got connected → mis-typed → boxed.
>
> **CORRECT APPROACH (for next session):** the ti_ side must be **DEFERRED**, not eager — keep a
> per-fn `ti_ret_seen` list; for an open (un-annotated) fn, COLLECT each return-expr type (and the
> fall-through) WITHOUT constraining ret_var; then AFTER the function's `ti_solve` (which resolves the
> vars) compute the JOIN of the *resolved* types (first concrete wins; a second DIFFERENT concrete →
> `any`; `any`/`unit`/`nothing`/`var` absorbed) and bind ret_var once. The IR side
> (`ir_analyze_return_type`) join is CORRECT AS DESIGNED IN THE PATCH: state machine `concrete`/`conflict`
> — an `any`/`val` return does NOT force widening (concrete wins), only two DIFFERENT concrete kinds →
> `any` (this is what keeps float fns float). Repros: `_anyret_repro.nova`, `_hetreturn_test.nova`,
> `_t1probe.nova`, `_anystr.nova`; strict error dump `_strict_errors_full.log`. Until 1.0 lands, 1.1/1.2
> remain blocked (any budget increase re-surfaces the 7 false-rejections).

## TIER 2 — Performance ceilings (the core is C-fast only on a narrow subset)

C-class scalar/struct math is real (~1.0–1.04× clang -O2, verified). But the moment code leaves that
subset, NOVA falls off a cliff — and the frameworks that need speed live off the cliff.

- **2.1 The uniform i64 value model is the ceiling.** Everything is a 64-bit handle → trivial inference
  and Python-simplicity (the win), but floats-in-lists are *boxed* and cross-function structs can't be
  register-split (no SROA). Cross-function struct code is capped at ~1.0–1.2× C (falsification 285846e).
  This is the **root cause** of 2.2 and 2.3, not a separate bug.
- **2.2 Float arrays — RE-MEASURED 2026-07-06 (the "8–120×" was one-sided; the real story is
  CONDITIONAL on ESCAPE).** Direct measurement (`_fa_bench*.nova`, sum of a 2M float array × 50 reps,
  vs clang `-O2` C):
  - **Homogeneous float list, no escape → 260 ms vs 108 ms C = 2.4× C.** The S4 floatlist fast path
    fires: `nova_rt_list_get_f` (raw double, no box-chase) + native `fadd double`. The residual 2.4× is
    per-element *call* overhead (vs an inlined load) + C's SIMD vectorization, NOT boxing.
  - **Same loop but the list ESCAPES** (passed to a helper → S4 taint drops the fast path for soundness,
    a callee could make it heterogeneous) **→ 30,361 ms = 281× C.** Reads fall to the generic boxed
    `nova_rt_index_get`. **THIS is the cliff** — and it's the real 2.2, not "every numeric loop".
  So: self-contained numeric loops are fine (2.4×); the catastrophic case is a float array that escapes
  and is then hot-read. **Fix = S4.2: a runtime elem-kind guard + native load on the tainted-but-still-
  homogeneous path (deopt), so escape doesn't force boxing.** **Blocks: Cortex/Pulse/Reactor** whenever
  arrays cross function boundaries (i.e. always, in real code). **Effort: L** (scoped S4.2), not the full
  XL raw-`double[]` rewrite — the fast path already exists, it just needs to survive escape.
- **2.3 HOF/closure arithmetic fully dynamic.** `map`/`filter`/`pmap` callbacks use runtime dispatch,
  ~50–100ns/op — and the tutorial *encourages* `map`/`filter` while the perf doc warns against them
  (a contradiction users will hit). Evidence: `where_nova_is_slow.nova:73-103`. **Effort: XL** (S5
  monomorphization — see note).
- **2.4 The fix is one campaign, and it doubles as a feature.** S3 (struct SROA) + S4 (raw float
  arrays) + S5 (monomorphic specialization, the "Julia endgame") close 2.1–2.3. S2 was attempted and
  reverted once (`PERFORMANCE_SPECIALIZATION.md`) — the retry is scoped there. **This is the single
  most valuable core investment** because it's *both* the perf fix *and* the generics enabler (Tier 3.2).
- **2.5 Continuous perf tracking — ✅ FIXED (e7841fa4, 2026-07-06).** The harness already
  existed (`bench/run_bench.ps1` times 5 benches → appends `{ts,commit,bench,mode,elapsed_ms,rc}` to
  `history.jsonl`; `bench/regression_check.ps1` compares the last 2 commits, fails >threshold%). The
  gap was that it wasn't RUN. Now wired into `nova_ci.ps1` as stage 2/3b (append + compare), **NON-FATAL**
  (times here are tiny/0–42 ms and memory-noisy, so a wobble must not red the CI; the FATAL codegen guard
  is `_perf_gate.ps1`). Baseline refreshed (`0cd6e97f`). Every perf change is now *measured*. NOTE: the
  benches are small; a future improvement is bigger workloads for higher signal. `-SkipPerfTrack` to skip.

**Why the future isn't bright if ignored:** Cortex and Pulse are *defined* by numeric throughput. If
float arrays stay 100× slow, those two frameworks can never be built honestly — you'd be shipping a
"NumPy killer" that loses to NumPy by 100×. **Tier 2 is the mountain: plan it as a dedicated multi-month arc, not a sprint.**

## TIER 3 — Language expressiveness (frameworks can't be *clean* without these)

- **3.1 No generics / parametric polymorphism.** Inference is HM-based but there are no user-facing
  generic types with constraints. Every framework API that should be `List<T>`/`Repo<T>` is worked
  around. **Blocks: ALL clean APIs.** **Effort: L.** *This is the single biggest expressiveness jump
  available.* Design it the NOVA way — inferred, zero-ceremony.
- **3.2 No interfaces/traits (feature #8, unbuilt).** Named in FORGE_STATUS as the missing piece for
  gRPC-service-from-types and polymorphic dispatch. **Blocks: Forge (gRPC), Mesh, any plugin system.**
  **Effort: L**, tightly coupled to 3.1.
- **3.3 First-class ADTs + exhaustive match.** `match` exists; enums-with-typed-payloads + exhaustiveness
  checking would make error/state modeling sound and clean (and closes 1.4). **Effort: M.**
- **3.4 (Optional, high-leverage) comptime.** Zig-style compile-time execution fits "the compiler is the
  genius" and *removes* the need for macros and some generics — it unifies rather than adds. **Effort: L.**

**Discipline note:** absorb the *idea*, unify it into the three primitives — do NOT bolt on each
language's syntax as a separate feature. That path is how NOVA becomes C++ (explicitly forbidden in
CLAUDE.md). The test for every addition: *does this make the language simpler and more unified, or does
it add a feature sitting beside the others?* If "beside" → reject.

## TIER 4 — Concurrency & runtime architecture (Reactor/Mesh live or die here)

- **4.1 N>1 I/O regresses.** Multi-carrier web I/O measured at **0.76–0.82×** single-core — more cores
  makes it *slower*. Evidence: audit scheduler + Go-judge findings. **Blocks: Forge at scale, Mesh,
  Reactor.** **Effort: L.** Must be fixed before claiming multi-core.
- **4.2 Linux FD_SETSIZE overflow.** `select()` with fd ≥ 1024 corrupts the carrier stack on the claimed
  Linux target (glibc `fd_set` not resized). Evidence: `nova_runtime.c:27`, `:6387`, `:6394`.
  **Effort: M.** Move to `poll`/`epoll` fully. CVE-class on Linux.
- **4.3 Cross-thread channel-send data race (N=1 default).** Sending from a non-carrier OS thread takes
  a path that touches scheduler state without the right lock. Evidence: `:7838`, `:7896`, `nova_sched_wake_one` `:4810`, `nova_rq_push` `:6019-6037`. **Effort: M.**
- **4.4 No preemption.** A CPU-bound task starves its carrier (cooperative only). Evidence:
  `forge_otp.nova:113`. **Blocks: Reactor (frame budget), Erlang-parity claims.** **Effort: XL.**
- **4.5 No per-process heaps.** One shared C address space + copy-on-send, not true isolation → a
  corruption is not contained (unlike BEAM). This is the honest limit behind "process isolation IS
  memory safety." **Effort: XL** (architectural). Decide explicitly whether to close or to re-scope the claim.
- **4.6 `remote_spawn` is a stub / unauthenticated RPC-by-name.** **Blocks: Mesh (distributed), Ops.**
  **Effort: L–XL.**
- **4.7 RC cycles leak forever.** No cycle collector; a cyclic graph never frees. **Effort: L.**

**Why it matters:** Reactor (games) needs a frame budget → needs preemption (4.4). Mesh (distributed)
needs real remote spawn (4.6). Forge-at-scale needs N>1 to not regress (4.1). These are not polish.

## TIER 5 — Platform reach ("runs anywhere" is Windows + WSL-once today)

- **5.1 No ARM/aarch64.** Fibers silently no-op on ARM. **Blocks: Edge (IoT), Apple Silicon, mobile.** **Effort: L.**
- **5.2 macOS never run** (epoll-only assumptions). **Effort: M–L.**
- **5.3 WASM frontend is a value-model proof, not a framework.** No SPA framework, no in-browser
  concurrency, no headless-browser CI. **Blocks: Prism (GUI-in-browser), the full-stack identity.** **Effort: XL.**
- **5.4 GPU is one hardcoded OpenCL vadd kernel** — no kernel-lowering compiler path. Evidence:
  `nova_runtime.c` ~`:20436-20523`. **Blocks: Cortex (AI accel), Reactor (rendering).** **Effort: XL.**
- **5.5 No GUI/windowing runtime at all.** **Blocks: Prism, desktop Reactor games.** **Effort: XL** (new runtime bridge — note: this is *runtime/platform* work the compiler enables but does not replace).
- **5.6 No CI on any platform but the dev's Windows box.** Linux was verified *once* manually on WSL2.
  **Effort: M.** "Runs anywhere" is unproven without per-platform CI.

## TIER 7 — Process & discipline (the meta-risk the audit ranked #1)

Not code — but the audit's single highest risk, because it *manufactures* all the tiers above.

- **7.1 Bus factor 1 at AI velocity.** Peaks of 51–116 commits/day; no human can review that. This is
  *why* Tier 0 holes and untested features exist. **Fix:** slow down; make review the bottleneck, not commits.
- **7.2 Rapid-dev ships syntax-checked-only code into the canonical framework** — including security
  features (admin perms/audit were shipped as stubs never wired into any route: `forge_admin.nova:334-364`).
  **Fix:** no security-facing code merges without a functional test.
- **7.3 310 orphaned test files** not wired into the CI gate → features regress silently.
  **Fix:** one manifest; every test in the gate or deleted.
- **7.4 `nova_ci -SkipReconverge` bypass** can silently skip the self-hosting check during rapid dev.
  **Fix:** never skip reconverge on a merge.
- **7.5 Doc sprawl:** ≥6 docs each claim to be canonical. **Fix:** one core plan (this file) + one Forge
  plan (FORGE_STATUS) + supersession banners on the dead ones.

## The build order (what to actually do, in sequence)

1. **Tier 0 (2–4 wks): close every runtime soundness hole.** The core becomes *trustworthy*. Nothing
   else is safe to build on until this is done.
2. **Tier 1 (3–5 wks): make the default type checker sound** (reset the budget, land strict-by-default,
   write negative tests). The core becomes *honest*.
3. **Tier 7 in parallel, forever: slow down, test before ship, one plan.** This stops new Tier 0/1 holes
   from being created faster than you close them.
4. **Tier 3.1+3.2 (L): generics + interfaces.** The core becomes *expressive* enough for clean framework
   APIs — and this is the prerequisite for gRPC-from-types, typed repos, plugins.
5. **Tier 2 (XL, dedicated arc): S3→S4→S5 specialization.** The core becomes *generally fast* — and S5
   is the same work that makes generics zero-cost. This unlocks Cortex/Pulse/Reactor.
6. **Tier 4 (L–XL): fix N>1, then preemption/distribution** as specific frameworks (Reactor, Mesh) demand them.
7. **Tier 5/6 as each framework requires** its platform (Edge→ARM, Prism→GUI/WASM, Cortex→GPU) and as
   adoption requires the toolchain (package registry, REPL).

**Rule:** do not start a framework whose blocking core gap is still open. Reactor needs Tier 2 + 4.4.
Cortex needs Tier 2 + 5.4. Prism needs 5.3/5.5. Forge (the one that's real) needs Tier 0/1 + 4.1 to be
production-grade. **Forge is the right framework to keep pushing precisely because its remaining blockers
are the core gaps everything else also needs.**

## The honest bottom line

The core is **real and rare**, but it is **not yet trustworthy (Tier 0/1), not yet general (Tier 2),
and not yet expressive (Tier 3).** Every one of those is fixable — none is a dead end. The frameworks
are the *reward*; the core is the *foundation*, and right now the foundation has cracks that a
9-framework tower would turn into a collapse. Fix the foundation in the order above and the future is
bright. Pour framework code onto the current core and you multiply its cracks nine times over.

**Build the compiler until it's trustworthy, sound, fast, and expressive. Then the frameworks are cheap.**
